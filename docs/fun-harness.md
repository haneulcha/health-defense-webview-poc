# 재미 하네스 — 좋은 게임인지 어떻게 판정하는가

작성 2026-08-14.

`?perf`가 성능을, `balance-report.test.ts`가 밸런스를 재는 것과 같은 위상의 도구입니다. 다른 점은 **재는 대상이 사람 안에 있다는 것**이고, 그래서 사람이 도는 트랙과 봇이 도는 트랙이 따로 있습니다.

상위 문서는 [`game-identity.md`](game-identity.md)입니다. **이 하네스는 정체성이 정한 것만 잽니다.**

---

## 0. 무엇을 재는가

**"재미"를 재지 않습니다.** *"이거 재밌나요?"* 는 실행 불가능할 만큼 넓은 질문이고, 게임 유저 리서치의 정설은 **어떤 종류의 재미인지를 먼저 정의하라**는 것입니다 (부록 출처).

우리는 정의했습니다 — [`game-identity.md`](game-identity.md) 3절의 **유능감**, 그중에서도 좁힌 형태인 **"내가 왜 이겼는지 내가 설명할 수 있다"**.

그래서 이 하네스의 1번 지표는 만족도가 아니라 **귀속(attribution)** 입니다.

---

## 1. 관찰 하네스 — 사람이 재는 것

일회성 실측입니다. `?perf`를 폰에서 직접 읽는 것과 같은 성격이고, 매 커밋마다 돌 수 없습니다.

### 1.1 지표 1 — 귀속

판이 끝난 **직후** 열린 질문 하나를 던집니다.

> 이겼을 때: **"방금 왜 이겼어요?"**
> 졌을 때: **"방금 왜 졌어요?"**

답을 세 갈래로 분류해 기록합니다.

| 분류 | 예 |
|---|---|
| **자기 판단** | "왼쪽을 비워뒀어요", "강화를 너무 늦게 했어요", "저기 먼저 놨어야 했는데" |
| **게임·운** | "갑자기 빨라지던데요", "그냥 어렵던데요", "쟤가 세더라고요" |
| **모름** | "글쎄요", "잘 모르겠어요" |

**첫 칸의 비율이 유능감의 직접 대리 지표입니다.** 다른 어떤 수치보다 정직합니다.

**패배 쪽 답이 승리 쪽보다 중요합니다.** [`game-identity.md`](game-identity.md) 6절이 금지한 것이 "왜 졌는지 안 보이는 패배"이고, 이 질문이 그 금지의 시험입니다.

### 1.2 지표 2 — PENS 유능감 5문항

판 직후 5점 척도. 자기결정이론 계열에서 게임용으로 만들어진 검증된 척도이고, 우리가 지어낸 질문보다 신뢰도가 높으며 회차 간 비교가 됩니다.

문항 예 — *"I felt very capable and effective"*, *"The game kept me on my toes but did not overwhelm me"*. 원문과 전체 문항은 부록 출처.

`[확인필요]` **한국어 번역을 그대로 쓸지, 표준 번역본이 있는지 확인해야 합니다.** 임의 번역은 척도의 검증 이력을 버리는 것이라 원문 대비 신뢰도가 떨어집니다.

1.1이 서술이고 이것이 눈금입니다. 둘 다 씁니다.

### 1.3 지표 3 — 행동

[`roadmap.md`](roadmap.md) 1번의 항목을 그대로 쓰되 기록 형식만 고정합니다.

| 항목 | 왜 |
|---|---|
| 첫 타워 배치까지의 시간 | 설명 없이 이해했는가 — [`game-identity.md`](game-identity.md) 7.4의 시험 |
| 웨이브 3 이전 이탈 여부 | 온보딩 실패의 가장 이른 신호 |
| **자발적 재도전 여부** | 몰입의 가장 정직한 지표. §4.2의 "무제한 연습이 튜토리얼을 대신한다"가 참인지 |
| 첫 체력 손실 웨이브 | 봇은 9웨이브. 사람은 훨씬 이를 것 |
| 오탭률 (노린 칸에 놓였는가) | 타일 48 CSS px가 실제 엄지에 맞는지 |

### 1.4 프로토콜 — 깨지면 그 회차는 무효

- **관찰자는 설명하지 않습니다.** 물어오면 *"어떻게 하고 싶으세요?"* 로 되돌립니다. **한 번이라도 설명하면 온보딩 측정이 통째로 죽습니다.**
- **게임을 변호하지 않습니다.** 그냥 말하게 두고 반박하지 않습니다.
- **경험자·비경험자를 분리 기록합니다.** 두 집단의 같은 단어가 반대 뜻입니다 ([`game-identity.md`](game-identity.md) 2.1).
- **테스터 본인 폰으로 합니다.** 데스크톱 마우스 플레이는 검증 대상 자체를 무효화합니다.
- 구성: 디펜스 경험자 2~3명, 비경험자 2~3명.

## 2. 자동 하네스 — 봇이 매 커밋 지키는 것

봇은 유능감을 못 느낍니다. 하지만 **유능감이 불가능해지는 조건**은 검출할 수 있습니다. 여기서 재는 것은 감정이 아니라 **구조적 전제조건**입니다.

`src/core/`가 렌더러를 모르고 `core/rng.ts`가 시드 결정론이라 아래가 전부 지금 구조에서 그대로 됩니다. `AGENTS.md`의 두 결정이 여기서 또 값을 합니다.

| 테스트 | 무엇을 지키나 | 지금 상태 |
|---|---|---|
| **비최적 봇도 이긴다** | 실력 축의 바닥 보장. §2.3.1의 "인풋 0에서도 이긴다"와 같은 계열, 다른 축 | 없음 — 봇은 항상 최적 배치 |
| **모든 시드가 클리어 가능** | 운이 승패를 가르지 않음 ([`game-identity.md`](game-identity.md) 6절) | 없음 — 웨이브 고정 |
| **결정 없는 다운타임 ≤ N초** | "자원이 있는데 할 게 없는" 연속 시간. 근거는 [`tower-defense-research.md`](tower-defense-research.md) 1절 | 없음 |
| **판 길이 3~4분** | [`roadmap.md`](roadmap.md) 3번의 기존 목표 | 5분대 |
| **잔여 체력이 분포한다** | 등급이 실제로 작동하는가 | 깨짐 — 봇 기준 거의 전원 만점 |

산출물: `src/core/competence.test.ts` (통과/실패), 밸런스 격자는 `balance-report.test.ts` 확장.

`[제안]` **"결정 없는 다운타임"의 판정 방법이 아직 없습니다.** "자원이 있고 살 수 있는 것이 있는데 봇이 아무것도 하지 않은 연속 시간"이 가장 단순한 정의지만, 봇이 일부러 모으는 구간과 구분되지 않습니다. 구현 시 정의를 먼저 확정해야 합니다.

## 3. 판정선

**하네스의 본체는 측정 도구가 아니라 여기입니다.** [`roadmap.md`](roadmap.md) 1번에는 관찰 *항목*은 있는데 판정선이 없어서, 지금 5명을 관찰해도 *"음, 3명이 다시 했네"* 에서 끝납니다.

판정선을 세 종류로 나눕니다. **이 구분이 이 문서가 기존 로드맵과 다른 지점입니다.**

### 3.1 지금 박는 것 — 논리적으로 정체성 위반인 극단만

관찰 전에도 참인 것들이라 지어낸 수치가 아닙니다. 그래서 전부 "아무도 / 0명" 형태입니다.

| 조건 | 뜻 |
|---|---|
| 비경험자 중 **아무도** 스스로 첫 타워를 못 놓음 | 온보딩 실패. 1.4가 관찰자 설명을 금지하므로 이건 곧 **게임이 못 가르친 것**입니다 ([`game-identity.md`](game-identity.md) 7.4) |
| 패배한 비경험자 중 **아무도** 왜 졌는지 설명 못 함 | 유능감 설계가 현재 게임에서 성립하지 않음 (3.1절) |
| **자발적 재도전이 0명** | "무제한 연습이 튜토리얼을 대신한다"는 §4.2의 전제가 거짓 |

### 3.2 1차 관찰이 만드는 것 — 중앙값은 전부 여기

첫 배치까지의 시간, 재도전율, PENS 점수, 첫 체력 손실 웨이브. **1차 관찰이 기준선을 만들고, 이후 변경은 "기준선 대비 악화 금지"로 판정합니다.** 절대 목표치는 관찰 후에 씁니다.

**여기서 숫자를 미리 정하지 않는 이유**는, 지어낸 숫자가 나중에 근거인 척하기 때문입니다. 1차 관찰의 임무는 판정이 아니라 **기준선 수립**입니다.

### 3.3 되돌림 트리거 — 어떤 결과가 무엇을 다시 쓰게 하는가

지금까지 어디에도 없던 것입니다. 미리 선언해야 결과를 보고 합리화하는 걸 막습니다.

| 관찰 결과 | 되돌리는 것 |
|---|---|
| 패배 원인 설명 불가가 다수 | [`game-design.md`](game-design.md) §5.2 등급 지표 + 피드백 연출 재설계 |
| 웨이브 3 이전 이탈이 다수 | [`game-identity.md`](game-identity.md) 7절 온보딩 재설계 |
| 승리해도 왜 이겼는지 모름 | 전투 가독성 문제 — 아트·연출 우선순위 상승 |
| 경험자만 즐거움 | [`game-identity.md`](game-identity.md) 2절의 1순위 유저 설정 자체를 재검토 |

## 4. 재지 않는 것

명시적으로 박아둡니다. 나중에 이 수치가 올랐다고 좋아하는 것을 막기 위해서입니다.

- **"재밌었나요?" 총점·별점.** 실행 불가능한 질문입니다 (0절).
- **세션 길이·일일 플레이 횟수.** [`game-design.md`](game-design.md) §1이 이걸 명시적으로 거부했으므로 **오르면 좋은 게 아니라 경고입니다.** 일반 게임에서 리텐션 개선으로 읽을 지표가 여기서는 반대 신호입니다.
- **리더보드성 비교 일체** (§5.1).

## 5. 두 트랙이 만나는 곳

**관찰이 자동 하네스의 상수를 만듭니다.**

"비최적 봇"의 *비최적*이 몇 %인지는 사람이 실제로 어떻게 두는지를 봐야 나옵니다. 1차 관찰에서 비경험자의 배치 패턴을 기록하고 그 수준으로 봇을 설정합니다.

**그 전까지 비최적 봇의 파라미터는 임의값이고, 임의값이라고 코드 주석과 이 문서에 적어둡니다.** 관찰 결과가 들어오면 교체합니다.

## 6. 언제 도는가

| 트랙 | 주기 |
|---|---|
| 자동 하네스 | 매 커밋 (`npm test`) |
| 관찰 하네스 | 마일스톤마다 |

`[결정]` **관찰은 최소 2회가 필요합니다.**

- **1차 — 현재 빌드.** 인풋 없는 10웨이브 캠페인. 여기서 답이 나오는 것: 배치 UX, 전투 자체의 재미, 온보딩, 성능(부수 효과로 실기기 5대분). **기준선이 여기서 만들어집니다.**
- **2차 — 데일리 구조가 들어간 뒤.** [`game-design.md`](game-design.md)의 핵심 가설은 1차로 검증되지 않습니다 — 축이 실제로 배치를 바꾸는가(§5.4), 결과 카드가 인과를 보여주는가(§5.5), 상한이 내일 다시 열게 하는가(§4.2). **2차 설계는 아직 없습니다.**

## 부록 — 이 하네스의 근거가 된 레퍼런스

[`tower-defense-research.md`](tower-defense-research.md)가 메커닉 층위를 다뤘고, 여기는 **가치 층위**입니다.

### A. Plants vs. Zombies — 비경험자를 끝까지 데려간 방법

George Fan이 GDC 2012에서 정리한 10가지. 우리에게 직접 걸리는 것들:

- **튜토리얼을 게임에 녹인다** — 별도 화면을 두지 않음
- **읽기보다 하기** — 손으로 해보고 결과를 본다
- **메커닉을 나눠서 도입한다** — 처음에 다 설명하지 않음. 몰입한 뒤에 배울 의지가 생긴다
- **단일 행위 시연** — 한 번 보여주면 충분
- **텍스트 8단어 이하**
- **적응형 메시지** — 못하는 사람에게만 안내가 뜬다. 잘하는 사람을 무시하지 않는다
- **시각으로 가르친다** — Peashooter의 큰 입이 발사를 말한다
- **기존 지식을 빌린다** — 심어진 식물은 못 움직인다는 걸 설명할 필요가 없다

그리고 그가 명시적으로 거부한 것: **하드코어를 위해 복잡하게 만들지도, 캐주얼을 위해 유치하게 만들지도 않았다.** [`game-identity.md`](game-identity.md) 5절이 여기서 나왔습니다.

**우리가 진 빚**: 은유를 '외부의 압박'으로 바꾸며 마지막 항목(기존 지식 빌리기)을 잃었습니다. 시각으로 갚아야 합니다 ([`game-identity.md`](game-identity.md) 4.1·7.4).

### B. Wordle류 — 하루 한 번의 의식

하루 한 번 열리는 힘은 셋에서 나옵니다. **그런데 셋 다 우리가 이미 포기했거나 금지했습니다.**

| Wordle의 장치 | 우리 상태 |
|---|---|
| **희소성** (하루 한 판, 몰아서 못 함) | 포기 — 무제한 플레이 (§4.2, 온보딩 때문) |
| **스트릭** | 금지 — §1.1 원칙 2 |
| **공유 그리드** | 리더보드만 금지(§5.1). **공유 자체는 아직 안 건드림** |

앞의 둘은 의도적 포기지만 **대체재가 문서에 없습니다.** 희소성이 주던 *"오늘 것을 다 했다"* 는 종결감은 지금 구조에서 **보상 상한**이 대신해야 하는데, §4.2는 상한을 파밍 방지 장치로만 정의해뒀습니다. **종결감 제공은 상한의 새 역할이고, 그러면 상한이 눈에 보여야 합니다.** 아직 설계되지 않았습니다.

### C. Kingdom Rush vs Bloons TD 6 — 배우기 좋은 것과 숙달하기 좋은 것

커뮤니티가 둘을 가르는 말이 우리에게 그대로 쓰입니다 — *"KR은 배우기 좋고 BTD6는 숙달하기 좋다. KR의 강점은 읽기 쉬운 레인과 빠른 맵 가독성."*

1순위 유저가 비경험자면 KR 쪽입니다. **168×312 제약이 여기서는 우리 편입니다** — 복잡하게 만들 수 없는 것이 가독성으로 되돌아옵니다.

### D. 측정 방법론

- *"이거 재밌나요?"* 는 너무 넓어서 실행 불가능하다. **어떤 종류의 재미인지 먼저 정의해야 한다.**
- 인디 규모의 최소 형태: **그냥 하게 두고 "어땠어요?"라고 묻고, 반박하지 않고 듣는다.**
- 표준 도구: GEQ, **IMI**(6개 하위척도 중 하나가 perceived competence), **PENS**(SDT 기반 게임 전용. competence 5문항).
